# Markdown 编辑器规范

本文档定义 OpenViking 文档编辑器的长期能力边界、Markdown 交换标准与实施约束。目标不是构建富文档产品，而是构建一个以 Markdown 为唯一事实来源、可协作、可导入、可导出、可被主流 Markdown 工具稳定消费的在线编辑器。

## 目标

统一以下四条链路的内容交换格式，确保内容可以无缝衔接：

1. CLI 上传 `.md`
2. 管理后台上传 `.md`
3. 在线编辑器保存 `.md`
4. WebDAV / 下载导出 `.md`

验收要求：

- 任意一条链路写入的 Markdown，都可以被其他三条链路继续消费。
- 导出的文档在 Typora、Obsidian、VS Code Markdown Preview、GitHub 等主流 Markdown 工具内可以正常呈现。
- 非 Markdown 范畴能力不得作为正式编辑能力暴露。
- 从飞书、钉钉粘贴的内容，只保留可映射为 Markdown 的语义；非 Markdown 能力直接丢弃。

## 交换标准

### 必须支持

以下能力属于正式交换标准，必须保证“编辑器编辑 -> Markdown 落盘 -> 再次打开恢复一致”：

- 标题 `#` 到 `######`
- 段落
- 粗体
- 斜体
- 删除线
- 行内代码
- 引用 `>`
- 无序列表
- 有序列表
- 任务列表
- fenced code block
- 代码块语言标记
- Mermaid 文本绘图代码块
- 图片
- 链接
- 分割线
- 表格

### 建议支持

以下能力仍属于主流 Markdown 生态，可在基础交换标准稳定后纳入：

- 自动链接
- 数学公式
- 脚注
- TOC
- Callout / Alert（采用受控 Markdown 扩展语法）
- 嵌套引用与复杂列表续行

### 必须移除

以下能力不属于 Markdown 交换标准，或当前系统无法稳定往返，必须从正式编辑能力中移除：

- 下划线
- 文本对齐
- 视频、音频、文件附件块
- 富卡片链接预览
- 任意嵌入块
- 多列布局
- 白板 / 自由画布
- 数据库块
- 任意无法稳定导出为 Markdown 的颜色、字号、背景等富文本装饰

### 飞书 / 钉钉粘贴保留规则

粘贴处理只做“Markdown 语义抽取”，不做平台对象兼容。

保留：

- 标题、段落
- 粗体、斜体、删除线、行内代码
- 引用
- 无序列表、有序列表、任务列表
- 链接
- 图片
- 代码块
- 表格
- Mermaid 文本绘图代码块
- 数学公式文本

直接丢弃：

- @ 人、@ 群、@ 文档对象
- 评论、批注、建议模式语义
- 文件附件块
- 视频、音频
- 卡片、嵌入、复杂对象
- 非文本绘图对象
- 平台私有布局和容器能力

## 当前现状结论

当前系统已完成以下能力闭环：

- 服务端 `DocumentContentCodec` 已支持标题、段落、粗体、斜体、删除线、行内代码、链接、无序列表、有序列表、任务列表、引用、代码块、Mermaid 代码块、图片、分割线和 GFM 表格的 Markdown 往返。
- 前端工具栏已收口到 Markdown 能力白名单，不再暴露下划线、文本对齐等非 Markdown 范畴能力。
- `/` 菜单已由 Markdown 白名单接管，视频、音频、文件、可折叠标题等默认非目标项已移除，仅保留 Markdown 相关块并新增 Mermaid 入口。
- 飞书 / 钉钉粘贴已升级为 Markdown 语义抽取，而不是纯文本降级。

## 实施原则

1. Markdown 是唯一事实来源。
2. 先收口，再增强；不允许继续暴露超出 Markdown 边界的能力。
3. 所有新能力必须同时补齐 parser、renderer、编辑器入口和测试。
4. 不以单一入口通过为验收，必须验证上传、编辑、导出全链路一致性。

## 上线门槛

每个任务完成前，至少满足以下门槛：

- 代码、文档和测试同步完成
- 相关能力具备明确的 Markdown 映射规则
- `git diff --check` 无格式问题
- 相关测试覆盖成功路径和降级路径
- 不引入新的非 Markdown 范畴能力
